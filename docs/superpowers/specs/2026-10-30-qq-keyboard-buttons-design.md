# QQ Bot 交互按钮设计

## 目标

将 QQ Bot 中所有需要用户从有限选项中选择的交互改为 QQ 官方 Keyboard 按钮，同时保留文本命令和按钮能力不可用时的纯文本降级。

## 范围

- 主菜单：每日签到、查询余额、绑定账号、AI 对话、充值中心、模型渠道。
- 站点选择：FluxA、Charity。
- 绑定流程中的“是/否”等有限选项。
- AI 对话中的分组和模型选择。
- 其他现有 handler 暴露的有限选项，只改变呈现和事件入口，不改变业务规则。

## 架构与数据流

`internal/qq` 增加结构化群消息 payload（`msg_type`、`markdown`、`keyboard`），并提供发送按钮消息的方法。Gateway 处理 `INTERACTION_CREATE`，从回调中读取按钮 `data`、群组和消息上下文，转换为现有 `qq.GroupMessage`，交由原有路由和 handler 处理。按钮的 `data` 使用现有命令/选项文本，以最大化复用并保持文本输入兼容。

按钮消息发送失败时，菜单和选项调用方发送原纯文本内容；失败只记录原始错误，不改变业务处理结果。

## 并发与安全

按钮回调沿用现有用户/群组流程状态和站点路由；不新增共享可变会话状态。按钮 payload 不包含密钥、验证码或其他敏感信息。回调中的用户和群组标识取自 QQ 服务端事件，不能由按钮 data 覆盖。

## 验证

- 单元测试覆盖按钮 payload 编码、`INTERACTION_CREATE` 解码和事件到文本命令的转换。
- handler 测试覆盖主菜单及站点选择使用按钮发送，并保留文本降级。
- 运行 `go test -race ./...`、`go vet ./...`、`go build ./...`。
- 发布镜像后在 FluxA 的独立 `/root/FluxA/qq-bot` compose 目录执行 pull/up，并检查容器日志。
